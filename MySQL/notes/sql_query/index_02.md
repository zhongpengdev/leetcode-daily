## 索引完全讲解

好，我把索引从头到尾、从里到外讲清楚。

---

## 一、索引是什么？（一句话版）

**索引就是数据库的"目录"**，用来快速定位数据，避免"翻遍整本书"。

---

## 二、为什么需要索引？没有索引会怎样？

### 没有索引：全表扫描

```sql
SELECT * FROM users WHERE age = 25;
```

没有索引时，需要顺序遍历

**时间复杂度：O(n)**  
**100万行数据 → 最多读100万行**

### 有索引：快速定位

有索引时，MySQL 的做法：

```
1. 去索引里找 25
2. B+树查找：3-4次定位
3. 直接拿到数据位置
4. 读取数据
```

**时间复杂度：O(log n)**  
**100万行数据 → 约3-4次定位**

---

## 三、索引的底层数据结构：B+树

**特点：**
1. 所有数据都在**叶子节点**（最下面一层）
2. 非叶子节点只存"路标"（指针）
3. 叶子节点之间用**双向链表**连接
4. 树的高度很低：3-4层能存上亿条数据

### 为什么用 B+树，不用二叉树？

| 数据结构 | 100万数据的高度 | 磁盘I/O次数 |
|---------|---------------|------------|
| 二叉树 | 约20层 | 20次 |
| B+树 | 3-4层 | 3-4次 |

**B+树矮胖，I/O次数少，更适合磁盘存储。**

---

## 四、索引的类型

### 按功能分

| 类型 | 关键字 | 特点 | 例子 |
|------|--------|------|------|
| 普通索引 | `INDEX` | 只加速查询 | `INDEX(name)` |
| 唯一索引 | `UNIQUE` | 加速 + 值不能重复 | `UNIQUE(email)` |
| 主键索引 | `PRIMARY KEY` | 唯一 + 非空 + 每表一个 | `PRIMARY KEY(id)` |
| 全文索引 | `FULLTEXT` | 大文本搜索 | `FULLTEXT(content)` |
| 空间索引 | `SPATIAL` | 地理位置 | `SPATIAL(location)` |

### 按结构分

| 类型 | 说明 | 特点 |
|------|------|------|
| 聚簇索引 | 数据按主键顺序存储 | 叶子节点存整行数据 |
| 二级索引 | 普通索引 | 叶子节点存主键值 |

**InnoDB 的主键索引就是聚簇索引**：找到了主键，就找到了整行数据。

**二级索引**：先找到主键值，再回表查数据。

---

## 五、聚簇索引 vs 二级索引（重点！）

### 聚簇索引（主键索引）

```
主键索引树：
        [50]
       /    \
    [20]    [80]
    /  \    /  \
  (id=1的整行)(id=2的整行)(id=3的整行)
```

**叶子节点直接存整行数据**。

### 二级索引（普通索引）

```
name索引树：
        ['李']
       /     \
    ['张']   ['王']
    /  \     /  \
  ('张三', id=1) ('李四', id=2) ('王五', id=3)
```

**叶子节点存的是 (name, 主键值)**。

### 回表

```sql
SELECT * FROM users WHERE name = '张三';
```

执行过程：
1. 走 `name` 索引，找到 `('张三', id=1)`
2. 拿到主键值 `id=1`
3. 再走主键索引，找到整行数据

**"回表"就是：先走二级索引，再走主键索引。**

## 六、索引的最左前缀原则（联合索引核心）

### 联合索引示例

```sql
CREATE INDEX idx_name_age ON users (name, age);
```

这个索引的存储顺序：

```
先按 name 排序，name 相同再按 age 排序

('张三', 18)
('张三', 25)
('李四', 20)
('李四', 30)
('王五', 22)
```

### 哪些查询能走索引？

| WHERE 条件 | 能否走索引 | 原因 |
|-----------|-----------|------|
| `name = '张三'` | ✅ 能 | 最左列存在 |
| `name = '张三' AND age = 25` | ✅ 能 | 用到了两列 |
| `age = 25` | ❌ 不能 | 跳过了最左列 name |
| `name LIKE '张%'` | ✅ 能 | 前缀匹配 |
| `name LIKE '%三'` | ❌ 不能 | 不是前缀匹配 |

**口诀：联合索引就像电话本，先按姓排，再按名排。只给名不给姓，找不到。**

## 七、什么时候用索引？什么时候不用？

### ✅ 适合建索引

- WHERE 条件经常用的列
- JOIN 连接用的列
- ORDER BY 排序的列
- GROUP BY 分组的列
- 区分度高的列（身份证号 > 性别）

### ❌ 不适合建索引

- 表很小（几千行）
- 频繁写入的表（索引拖慢写入）
- 区分度低的列（性别只有男/女）
- 长文本列（除非前缀索引）

## 八、索引失效的常见情况（面试必问）

```sql
-- 1. 对列用了函数
WHERE YEAR(create_time) = 2024  -- ❌
WHERE create_time >= '2024-01-01' AND create_time < '2025-01-01'  -- ✅

-- 2. 隐式类型转换
WHERE phone = 13800138000  -- ❌ phone 是 VARCHAR
WHERE phone = '13800138000'  -- ✅

-- 3. LIKE 以 % 开头
WHERE name LIKE '%张三'  -- ❌
WHERE name LIKE '张三%'  -- ✅

-- 4. OR 连接的条件
WHERE name = '张三' OR age = 25  -- ⚠️ 两边都有索引才走

-- 5. 使用 != 或 <>
WHERE age != 25  -- ❌ 大多数情况不走

-- 6. 使用 IS NULL / IS NOT NULL
WHERE age IS NULL  -- ⚠️ 可能走也可能不走

-- 7. 联合索引没遵守最左前缀
-- 索引 (a,b,c)
WHERE b = 1 AND c = 2  -- ❌ 没用到 a
WHERE a = 1 AND c = 2  -- ⚠️ 只用到 a
WHERE a = 1 AND b = 1 AND c = 1  -- ✅ 全用
```

## 九、如何验证索引是否生效？

### 用 EXPLAIN

```sql
EXPLAIN SELECT * FROM users WHERE name = '张三';
```

### 重点看这些列

| 列 | 好 | 坏 | 说明 |
|---|----|----|-----|
| `type` | `ref`, `range`, `const` | `ALL` | ALL 代表全表扫描 |
| `key` | 有索引名 | `NULL` | NULL 代表没用索引 |
| `rows` | 数字小 | 数字大 | 扫描的行数 |
| `Extra` | `Using index` | `Using filesort` | 前者好 |
| `Extra` | - | `Using where` | 代表回表了 |

### type 好坏排序

```
const > ref > range > index > ALL

const：主键/唯一索引等值查询（最快）
ref：普通索引等值查询
range：范围查询
index：遍历整个索引（比 ALL 好一点）
ALL：全表扫描（最慢）
```

## 十、覆盖索引（性能优化利器）

**覆盖索引 = 要查的列都在索引里，不需要回表**

```sql
-- 索引：idx_name_age (name, age)

-- 覆盖索引查询（不需要回表）
SELECT name, age FROM users WHERE name = '张三';
-- Extra 显示：Using index

-- 非覆盖索引查询（需要回表）
SELECT * FROM users WHERE name = '张三';
-- Extra 显示：Using index condition（回表了）
```

**覆盖索引的好处**：避免回表，速度快 2-3 倍。

---

## 十一、索引的代价

不是索引越多越好，每个索引都有代价：

| 代价 | 说明 |
|------|------|
| 空间 | 每个索引都占磁盘空间 |
| 写入变慢 | INSERT/UPDATE/DELETE 需要同时更新索引 |
| 维护成本 | 冗余索引需要清理 |

**经验法则：一张表索引不超过 5-6 个。**

---

## 十二、如何设计好索引？

### 三步法

1. **找出核心查询**：哪些 WHERE、JOIN、ORDER BY 最频繁？
2. **选择区分度高的列**：身份证号 > 姓名 > 性别
3. **按最左前缀原则建联合索引**：把区分度高的放左边

### 例子

```sql
-- 常见查询
WHERE name = '张三'
WHERE name = '张三' AND age = 25
ORDER BY created_at

-- 推荐索引
CREATE INDEX idx_name_age ON users (name, age);  -- 覆盖前两个查询
CREATE INDEX idx_created_at ON users (created_at);  -- 覆盖排序
```

## 一句话总结

> **索引是 B+树 结构的目录，用 O(log n) 的时间快速定位数据，避免 O(n) 的全表扫描。核心是选对列、遵守最左前缀原则，同时避免索引失效的写法。**
