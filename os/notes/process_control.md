# 进程状态转换的实现方式

## 实现状态转换的三种机制

### 1. 原语（内核态执行）

原语是操作系统内核中**不可中断**的基本操作，具有**原子性**——要么全部执行完，要么完全不执行。

实现原子性的两种方式：
- **关中断**：执行原语前屏蔽中断，完成后恢复
- **利用特殊指令**：如 `Test-and-Set`、`Compare-and-Swap` 等硬件级原子指令

原语只在**内核态**下执行，用户程序不能直接调用，必须通过系统调用陷入内核。

进程控制原语：

| 原语 | 状态转换 | 触发者 |
|------|----------|--------|
| `create` | 新建 → 就绪 | 父进程/用户 |
| `destroy` | 运行/阻塞 → 终止 | 进程自己或父进程 |
| `block` | 运行 → 阻塞 | 进程自身（等I/O等资源） |
| `wakeup` | 阻塞 → 就绪 | 另一个进程或中断处理程序 |
| `schedule` | 就绪 → 运行 + 运行 → 就绪 | 调度程序 |

### 2. 系统调用（用户态 → 内核态的桥梁）

用户程序想让操作系统做事，必须通过**系统调用**触发状态转换：

```
用户程序调用 read()
  ↓
触发软中断（陷入指令），CPU 从用户态切换到内核态
  ↓
内核执行对应的原语（如果数据没准备好 → block 当前进程）
  ↓
返回用户态（或切换到另一个进程）
```

常见系统调用与对应的状态转换：
- `fork()` → 创建新进程（新建 → 就绪）
- `exit()` → 进程自我终止（运行 → 终止）
- `wait()` → 等待子进程结束（运行 → 阻塞）
- `exec()` → 替换当前进程的代码和数据

### 3. 中断（被动触发状态转换）

中断是**硬件或软件主动打断 CPU**，是很多状态转换的触发源：

- **I/O 中断**：设备完成操作 → `wakeup` 等待该 I/O 的进程（阻塞 → 就绪）
- **时钟中断**：时间片用完 → 当前进程被强制 `schedule` 出去（运行 → 就绪）
- **异常中断**：进程出错（如段错误）→ `destroy` 该进程（运行 → 终止）

## 三者的关系

```
用户程序
  │  系统调用（主动请求）
  ↓
系统调用处理程序
  │
  ↓
  原语（执行具体操作）
  │
  ↓
  进程状态发生转换
  │
  ↑
  中断（被动触发，也可能间接调用原语）
```

- **系统调用**是入口（用户主动要做什么）
- **原语**是执行者（内核具体怎么改状态）
- **中断**是触发器（外部事件驱动状态变化）
