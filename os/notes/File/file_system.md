# 常见文件系统，以及它在解决什么问题

常见文件系统梳理：

1. NTFS：windows默认文件系统，不跨平台，最大单文件上限16TB
2. ext4：Linux默认，最大单文件上限16TB
3. APFS：苹果mac默认
4. exFAT：几乎没有文件大小显示（16EB），兼容性最好，U盘一般用它。
5. FAT32：老旧小容量设备首选，兼容性最好，各种操作系统一般都能解析，最大单文件上限4GB。
6. ZFS(Zettabyte File System)：存储服务器，NAS使用，自带RAID，写时复制，不仅是文件系统，连带把逻辑卷管理（LVM）和硬件控制都做了。
7. Btrfs (Better FS)：代 Linux（如群晖 DSM、Fedora）的主力企业级文件系统，支持动态卷扩容、写时复制、秒级快照。比 ZFS 更轻量，对内存开销没有 ZFS 那么恐怖。

# Inode：节点索引

**inode 才是文件本身。** 

## inode 里存了什么

```
inode 编号
├── 文件类型（普通文件、目录、软链接...）
├── 权限（rwxr--r--）         
├── 所有者 uid / gid
├── 大小、时间戳（创建/修改/访问）
└── 数据块指针（指向磁盘上真正存数据的区块）
```

**1. mv 大文件为什么瞬间完成？**
mv 只改目录项（把文件名指向另一个目录），不动 inode，更不动数据本身。

**2. 硬链接 vs 软链接**
- 硬链接：两个文件名 → **同一个 inode**。删一个，另一个还能用。
- 软链接：一个独立文件，内容是”目标路径”。原文件删了，软链接指向空路径，就废了。

# Superblock

Superblock 是**整个文件系统的元信息的集合**，记录了这个**分区**有多少 inode、多少空闲块、inode 表在哪。

没有 superblock，操作系统连 inode 表都找不到。

Superblock → 找到 inode 表 → 目录项拿到 inode 编号 → 查 inode → 拿到数据块指针 → 读出文件内容。
